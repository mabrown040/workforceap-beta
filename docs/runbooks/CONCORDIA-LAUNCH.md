# Concordia High School Launch Runbook

Operations runbook for the 2026 Concordia High School (CHS) enrollment pilot.
Current as of Phase B3, which replaced the hand-built static Concordia page with
a database-driven route at the same URL.

## Overview

- **Student link:** https://www.workforceap.org/enroll/concordia
- **Partner slug:** `concordia` — **must** match the `/enroll/<segment>` above. That URL segment IS the partner slug: middleware derives the partner ref from it, drops a 30-day attribution cookie, and `/api/apply/signup` resolves it against `Partner.slug`. If the two ever drift, students who use the link get no attribution and no funding stamp. The constant lives in `lib/partners/chsPartner.ts` (`CHS_PARTNER_SLUG`) and is pinned by `lib/partners/chsPartner.test.ts`.
- **Referral code:** `chs2026` — the link carries it automatically; it also works directly at `/apply?ref=chs2026` (per-program: `/apply?ref=chs2026&program=<slug>`).
- **Sponsorship window:** 2026-01-01 → 2026-12-31 UTC, term label `2026`, funding source `PARTNER_ORG`. Outside that window nothing is stamped automatically **and the enrollment page stops making any cost claim** — extend `sponsorshipEndsAt` in `/admin/partners` before the pilot rolls into a new term.
- **Seat cap: intentionally unset (uncapped).** Spend is controlled by the manual Coursera activation gate below (`courseraEnrollmentApproved` per consented student), which is the real limiter. A seat cap here would only add a second limiter that silently leaves students unfunded with a staff-only alert. Set one in `/admin/partners` only if you deliberately want that behavior — **and see "What the public page says" below, because a reached cap removes the cost sentence from the student page entirely.**
- **The partnership:** there is no cost to Concordia High School students for 2026 to enroll in these certificate programs — enrollment is sponsored through the WorkforceAP–Concordia High School partnership. Partner contact: Dr. Marianne Rader (marianne.rader@chsaustin.org).
  - This sentence is generated by `buildSponsorshipMessage()` in `lib/partners/sponsorship.ts` and is the **only** place public cost copy is written. The page, the page description, and the email draft below all use this wording — if you change one, change `sponsorship.ts` and let the page follow.
- **Where attribution lands:**
  - `Application.referralSource = 'partner_ref:chs2026'`
  - A `PartnerReferral` roster row under the CHS partner
  - Visible on the partner detail page at `/admin/partners` (CHS partner detail)

## ORDER OF OPERATIONS — read before deploying

`/enroll/concordia` is a **dynamic route backed by the `Partner` row**. It is not
a static page and it does not exist without data:

> **The partner row must exist with `enrollmentPageEnabled = true` BEFORE — or
> immediately after — the deploy. Between a deploy and partner creation the URL
> returns 404. Do not share the link with anyone until the row exists and the
> page returns 200.**

Phase A's version of this runbook listed "deploy, then create the partner" with
no warning attached, which is now a trap: on a fresh production database that
sequence leaves the student link dead for however long step 2 takes.

### Step 0 — Pre-flight: what is already in production?

Run this against prod **before** anything else:

```sql
SELECT id, slug, referral_code, active, status, enrollment_page_enabled
FROM partners
WHERE referral_code = 'chs2026' OR slug IN ('concordia', 'concordia-high-school');
```

Read the result:

| What you see | What it means | What to do |
| --- | --- | --- |
| No rows | Fresh install | Normal path — the script creates the partner. |
| One row, `slug = 'concordia'` | Already correct | Script reports `OK (no changes needed)` or `UPDATED`. |
| One row, `slug = 'concordia-high-school'`, `referral_code = 'chs2026'` | The Phase A row. Phase A's runbook told you to create it at that slug; Phase B2 shortened the constant to match the printed link. | **Nothing manual.** The script now ADOPTS it — see below. |
| A row with `referral_code = 'chs2026'` under some **other** slug/name | Somebody else owns the code | The script refuses and names the owner. Resolve in `/admin/partners` first. |

**Adopt-and-rename (automatic).** If there is no `concordia` partner but a
`concordia-high-school` one owns `chs2026`, `scripts/create-chs-partner.ts`
renames that row in place, applies the launch invariants, and prints:

```
ADOPTED (renamed concordia-high-school → concordia) partner "Concordia High School" — id=…
```

It never renames a `concordia-high-school` row that does **not** own `chs2026` —
that would be somebody else's partner. Covered by
`lib/partners/chsPartnerProvisioning.test.ts` (fresh create, adopt-and-rename,
already-correct no-op, third-party conflict).

## One-Time Launch Steps

1. Run the **Step 0 pre-flight query** above and know which row you have.
2. Deploy the merged branch to production.
3. Create/adopt the partner record against prod, **immediately** after the deploy:
   ```bash
   node scripts/prisma-env.js npx tsx scripts/create-chs-partner.ts
   ```
   Expect one line — `CREATED`, `ADOPTED`, `UPDATED`, or `OK (no changes needed)` — carrying:
   - [ ] the partner id
   - [ ] `slug=concordia`
   - [ ] `referralCode=chs2026`
   - [ ] `status=active`
   - [ ] `sponsoredEnrollment=true` — without this the automatic funding stamp never fires
   - [ ] `enrollmentPageEnabled=true` — **without this `/enroll/concordia` returns 404**
   - [ ] `seatCap=uncapped`

   The script is idempotent and non-clobbering: re-run it as many times as you like.
4. **Prod smoke-test checklist:**
   - [ ] `curl -sI https://www.workforceap.org/enroll/concordia` returns **200**, not 404.
   - [ ] Visit `/enroll/concordia` on mobile **and** desktop; page renders, programs listed, CTAs work.
   - [ ] The cost sentence is present and reads "…sponsored through the WorkforceAP–Concordia High School partnership."
   - [ ] Complete a throwaway signup via a program card CTA, using the **Under 18** age band.
   - [ ] Verify in admin: Application is **PENDING** with `referralSource = 'partner_ref:chs2026'` and a `PartnerReferral` row exists under the CHS partner.
   - [ ] Verify both Resend emails (verification + confirmation) and the admin alert fired.
   - [ ] Verify the test member is **ABSENT** from `/admin/wioa-screening` (CHS students are not WIOA-screened).
   - [ ] Confirm the application notes start with `MINOR — parental consent required before activation`, and that the enrollment line reads `Student self-reported enrollment (NOT parental consent): …`.
   - [ ] On the school page, click **"This isn't my school"** and confirm you land on the standard apply wizard with the two funding questions back.
   - [ ] Bulk-approve the test application with the **reviewer** attestation checkbox (see the warning under "Ongoing Cadence" — it is not the same attestation as the student's).
   - [ ] Run the funding stamp script:
     ```bash
     node scripts/prisma-env.js npx tsx scripts/stamp-chs-funding.ts
     ```
   - [ ] Verify the test member's primary enrollment shows `fundingSource = PARTNER_ORG`.
   - [ ] Erase the test member.

## The Enrollment Page — What Each State Means

`/enroll/concordia` has three outcomes. Knowing which one you are looking at
tells you exactly which column to check.

| What a student sees | Cause | Lever |
| --- | --- | --- |
| **404** | No partner row with `slug = 'concordia'`, **or** `enrollmentPageEnabled = false`. | Run the create/adopt script (Step 3), or flip `enrollmentPageEnabled` in `/admin/partners`. |
| **200, "Enrollment through Concordia High School is temporarily paused"** | The row exists and the page is enabled, but `active = false` or `status != 'active'`. | This is the **intentional pause lever**. Flip `active` / `status` in `/admin/partners` to pause or resume. |
| **200, full page** | Everything is on. | — |

**Paused is deliberately not a 404.** Students are holding printed links and a
dead URL reads as "this was a scam". The paused page explains, tells them to see
their counselor, and links to `/programs`.

### What the public page says about cost

The cost sentence appears **only** while the sponsorship is genuinely in force.
It disappears — replaced by neutral counselor guidance, with the programs still
listed — in all three of these cases:

- `sponsoredEnrollment = false`
- `now` is outside `sponsorshipStartsAt` … `sponsorshipEndsAt`
- **a `sponsorshipSeatCap` is set and has been reached**

That last one is the surprising one: setting a cap in `/admin/partners` means
that the moment the funded seats are consumed, every student who opens the link
sees a page that makes **no cost claim at all**. That is intentional — promising
sponsored enrollment on a page whose funding is exhausted is a promise we cannot
keep — but it means the cap is a *public-facing* switch, not just an internal
one. The page never shows a remaining-seat count.

### Where the program cards come from

- If the partner has **no** `PartnerProgramCatalog` rows, the page renders the
  five default school tracks from `SCHOOL_DEFAULT_SLUGS` in
  `lib/partners/enrollmentPage.ts` — in code, not in the database. This is the
  state Concordia launches in.
- **The fallback is all-or-nothing.** Adding **one** catalog row replaces all
  five defaults with that single program; it does not append to them. If you
  curate the catalog, enter every program you want shown, in one sitting.
- Rows whose `programSlug` is not in the canonical program list are skipped and
  logged. If *every* row is bad, the page falls back to the five defaults rather
  than rendering an empty catalog.

## Rollback

The Phase B3 dynamic page can be reverted without any database access:

```bash
git revert <B3 commit>   # cacf1b0f + this follow-up
```

That restores the static Astro page at the same URL in one build cycle. The
partner row is harmless if left in place — it simply stops being read.

For a *fast* rollback with no deploy at all, flip `active = false` in
`/admin/partners`: the URL keeps returning 200 with the paused explainer.

## GATE — Before Sending the School Email

Confirm the available Coursera B4B seat count is **≥ the expected CHS cohort size**. Every activation consumes a paid seat — see `docs/COURSERA-ENROLLMENT-FLOW.md`. Do not send the email below until seats are confirmed.

## Ongoing Cadence (Daily During Launch Week, Then Tue/Fri)

Review daily during launch week, then settle into a Tue/Fri cadence. Each review:

1. Review pending CHS applications (filter by the CHS partner / `partner_ref:chs2026`).
2. Cross-check **each** applicant against the school's consent roster.
3. Bulk-approve **ONLY** consented students. For this cohort, the **reviewer** attestation checkbox in admin means **"consent verified."** See the warning directly below before you tick it.
4. Run the stamp script after each approval batch (until Phase B automates it):
   ```bash
   node scripts/prisma-env.js npx tsx scripts/stamp-chs-funding.ts
   ```
5. Flip `courseraEnrollmentApproved` **ONLY** for students who are both approved **and** consented.

### ⚠️ "Attestation" means two different things — do not confuse them

| | Who makes it | Where you see it | What it proves |
| --- | --- | --- | --- |
| **Applicant attestation** | The **student**, on the apply form | `Application.notes`, as `Student self-reported enrollment (NOT parental consent): <school>` | Only that the student says they attend that school. **Nothing about a parent.** |
| **Reviewer attestation** | **You**, in admin at approval time | The bulk-approve checkbox | That *you* have checked this student against the school's returned consent forms/roster. |

A student cannot consent on their own behalf. **The presence of the applicant
line in the notes is not permission to tick the reviewer checkbox.** The only
thing that authorises that tick is a signed form or a roster entry from the
school.

Every application from a minor now carries **`MINOR — parental consent
required before activation`** as the FIRST line of `Application.notes` and of
the admin alert email. If you see that line, the reviewer attestation stays
un-ticked until you have the school's paperwork in hand.

## Consent Rules

- Consent gates **SEAT ACTIVATION**, never signup. Students may apply immediately; nothing is activated until consent is on file.
- Minors' Profile consent fields (`isMinor`, guardian fields, `parentalConsentGiven`, `schoolName`) are **backfilled by admin** from the school's returned forms/roster. A structured admin write path ships in Phase B — until then, the school's signed forms plus a roster spreadsheet ARE the record.
- **Guardian revocation:** un-flip `courseraEnrollmentApproved`, pause the enrollment, and notify the school.

## Week 2 — Partner Portal

Invite Dr. Rader (or a designated counselor) to the partner portal via the **Invite** button on `/admin/partners/<id>`. Roster, milestones, and exports work today.

## Failure Playbook

| Failure | What happens | Fix |
| --- | --- | --- |
| Student bypasses the link (uses the standard Apply page) | **NO partner attribution** | Reconcile the pending queue against the school roster by name/email. An admin linking affordance ships in Phase B; until then track manually. |
| Duplicate email (student already has an account) | Signup blocked on existing email | Student logs in, or resets their password. |
| Verification email filtered by school mail | Student never verifies | Personal-email fallback for the student; ask CHS IT to allowlist workforceap.org sending domains. |
| `/enroll/concordia` returns 404 | No partner row, or `enrollmentPageEnabled = false` | Run the create/adopt script (Step 3) and re-check the pre-flight query. See "What each state means". |
| Page loads but shows the paused explainer | `active = false` or `status != 'active'` | Intentional pause lever — resume in `/admin/partners`. |
| Page loads but the cost sentence is missing | Sponsorship not in force: off, outside the window, or a **seat cap has been reached** | Check `sponsoredEnrollment`, the window dates, and `sponsorshipSeatCap` in `/admin/partners`. |
| Page shows only one program instead of five | A `PartnerProgramCatalog` row was added — the code fallback is all-or-nothing | Enter the rest of the catalog rows, or delete the row to return to the five defaults. |
| Script exits 1 with a referral-code conflict | Another partner owns `chs2026` | The script names the owner and changes nothing. Fix that partner in `/admin/partners`, then re-run. |
