# WorkforceAP — Q3 2026 Plan: QA Fix Queue + Sprint Roadmap

**Date authored:** 2026-05-18
**Scope:** ~16 weeks (Sprints 1–8 across two-month tracks: launch readiness + retention)
**Audience:** Founders, product, eng, marketing
**Status:** Draft for review. Built from a parallel fan-out audit of the codebase (6 QA passes + 3 strategy passes).

> Read order: §0 → §1 (decide what to ship) → §2 (decide where to invest). §3 is the data behind it.

---

## §0. Executive summary

WorkforceAP is structurally ready for paid acquisition once state approval lands, but a non-trivial amount of platform debt would compound under 10–100× traffic. The audit surfaced **two distinct workstreams**:

1. **A defensive QA queue** — 19 P0/P1 items that must clear before ad spend turns on. Most are compliance- or trust-shaped (audit retention, multi-tenancy gaps, apply-funnel validation, missing telemetry on login). None require a redesign.
2. **An offensive product roadmap** — 8 sprints across growth, retention, and platform tracks. Net thesis: build moats on the data side (O*NET-fed outcomes engine, employer marketplace, AI coach with memory) and the compliance side (funder analytics) because those are hardest to copy and create compounding LTV.

The biggest single underweight finding: **funnel telemetry is incomplete**. We track parts of apply but not login, not MFA, not first-action, not Coursera launch, not UTM attribution. Without these, the ad-spend ROI question is unanswerable. **Sprint 1 fixes this before Sprint 7 turns on ads.**

The biggest single risk: **`scripts/safe-migrate.cjs` silently marks failed migrations "applied"** — this is the root cause of the `fix_schema_drift_*` migration history. Fix in Sprint 3 (platform track) before anything else schema-related ships.

The biggest single opportunity: **`/partners` redirects to `/`**. This is a B2B channel with no landing page. Sprint 4 ships it. Partners already have a working portal (just no marketing front door).

**Recommended first 4 weeks:** finish the QA P0/P1s (§1), wire telemetry (Sprint 1 of growth track), finalize multi-tenancy (Sprint 1 of platform track), launch `/partners` page (Sprint 4 of growth track pulled forward).

## §1. QA fix queue

Consolidated from 6 parallel agents (portal, marketing, mobile/a11y/i18n, perf/telemetry/funnel, API security, build hygiene). Prioritized P0–P3. Every line cites a file path so this is workable as-is.

**Priorities:**

### §1.1 P0 — must fix before ads turn on

#### Security & compliance

- **[P0]** xAPI tables missing `organization_id` for multi-tenancy. `lib/xapi/mappings.ts:51-123` — `coursera_identity_mappings`, `coursera_xapi_events`, `coursera_unmatched_actor_alerts` are global. Once multi-tenant goes live, a learner under Org A resolves to any org via xAPI ingest; completions credit the wrong tenant. **Fix:** add `organization_id NOT NULL` + filter every join.
- **[P0]** RLS GUC mechanism is non-functional — `orgId` always null. `lib/auth/server.ts:99-108` — `resolveAuthGucContext` hardcodes `orgId: null` while PgBouncer transaction-mode pooling means the GUC doesn't persist across queries. Defense-in-depth is theatre today; everything works only because postgres bypasses RLS. The moment `FORCE ROW LEVEL SECURITY` is enabled (migration exists, deferred), admin paths break. **Fix:** wrap authenticated route DB work in `$transaction`; resolve `orgId` from `getActorOrganizationId(user.id)` and pass to `buildGucContext`.
- **[P0]** Dead `agent_tasks` code that throws at runtime. `lib/swarm/taskQueue.ts:32-126` — calls `prisma.$queryRawUnsafe('INSERT INTO agent_tasks ...')` but no schema/migration defines that table. Any caller hits "relation does not exist." **Fix:** either ship the table + migration, or delete the dead code (one or the other, in a single commit).
- **[P0]** Admin redirect-loop risk on slow `isAdmin()`. `app/admin/page.tsx:83-88` — if `isAdmin()` is slow/returns false, redirect to `/dashboard`. If `/dashboard` redirects based on role again, possible loop. No timeout, no feedback. **Fix:** add timeout + user feedback if role check hangs.
- **[P0]** Login form may silently fall back on bad `redirectTo` param. `app/(auth)/login/LoginForm.tsx:311-312` — sanitization fails silently, falls back to `/dashboard`; if attacker crafts `?redirectTo=/admin`, no error surfaces. **Fix:** log sanitization failures; reject with explicit error.

## §5. Multi-million-dollar moats

Four structural advantages worth investing in. Each is 3–9 months. Sprints above lay foundation.

### §5.1 O*NET-fed outcomes matching engine
Integrate BLS O*NET data + WorkforceAP placement data → continually-improving program recommendations. Members see "CompTIA A+ → 87% probability IT Support role, $55K Austin median." Employers see "Need 50 helpdesk staff → here's the right cohort to feed."

**Why moat:** Proprietary data. Bootcamps don't have employment outcome feedback loops. Improves with every placement.

**Codebase leverage:** Skill mapper, training program model, placement records already in schema.

### §5.2 Employer pipeline marketplace
Move from "we refer graduates to you" → "employers bid for cohort slots." Employer posts "need 20 AWS engineers Q3, $100K/hire" → WorkforceAP creates dedicated cohort → graduates pre-matched + interviewed pre-graduation.

**Why moat:** Two-sided network effects. Revenue per member jumps 3–5× (15–20% placement fee or employer subscription).

**Codebase leverage:** Employer portal, JobApplication, EmployerMatch all exist.

### §5.3 Counselor automation + persistent AI career coach
Current state: Lilley has compact persistent member memory; the other AI tools are still mostly stateless. Extend that foundation into a persistent coach that learns goals, nudges proactively, and generates personalized study plans. Counselor spends 30% on motivation + placement, 70% less on diagnosis.

**Why moat:** Reduces cost-to-serve from ~$2K/member to ~$300/member. Enables profitability at scale + geographic expansion (fewer counselors needed).

**Codebase leverage:** R2 sprint (AI coach memory) is foundation; AI tools already shipped; just need persistent context.

### §5.4 Compliance-as-a-product for funders
Workforce boards have no good outcome-reporting software. Package WorkforceAP's admin analytics + WIOA reporting as SaaS for other workforce boards. *"450 trained, 340 placed (75%), avg salary lift $18K, ROI $4.2M taxpayer value"* — exportable dashboards.

**Why moat:** Guaranteed recurring revenue + political cover for expansion + exit potential (Workiva, HireClarity, PE roll-up).

**Codebase leverage:** Admin analytics + audit log + i18n + multi-tenancy (once P1 finalized) all in place.

## §8. Risks & open questions

### Product
1. **AI tool stickiness collapse.** Tools are novelties without memory. Sprint R2 is mandatory; bail if 2+ tools/week is still flat 4 weeks after launch.
2. **Counselor workload paradox.** Automating alerts may *increase* perceived workload if queue looks overwhelming. Red/yellow/green triage matters; test with 2 counselors first.
3. **Coursera completion cliff.** No data on pass rates / withdrawal reasons. Add dropout survey; coordinate with Coursera account manager.
4. **Employer demand vs. supply.** Marketplace is chicken-egg. Pilot with 1–2 employers; reverse-engineer member pool to their roles.
5. **Placement survey fatigue.** 30d (not 90d), 2-min max, SMS option, $50 incentive.

### Data gaps to fill
- No baseline AI tool usage by lifecycle stage. Instrument first, optimize second.
- No data on State B → C drop-out reasons. Add transition survey.
- Counselor capacity is unknown. Ask ops; auto-assignment needs utilization policy.
- No employer-willingness-to-pay data. Get 3 LOIs from top hiring partners before Sprint G3 ships.

### Leadership decisions needed
1. **Monetization priority.** Employer tiers (faster revenue) vs funder analytics (more mission-aligned)?
2. **Premium member tier ethics.** Charge members or only employers bulk-buying? Define policy early.
3. **Counselor automation scope.** How much does cron/AI replace human judgment? Where are the guardrails?
