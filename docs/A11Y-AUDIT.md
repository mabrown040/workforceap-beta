# Accessibility Audit — WorkforceAP

**Date:** 2026-05-13  
**Auditor:** Dench (subagent)  
**Scope:** High-traffic public and portal pages  
**Methodology:** Static code review + manual ARIA/semantic checks against WCAG 2.1 AA

---

## Methodology

1. **Automated pattern checks** — grep for missing `alt`, unlabeled inputs, empty headings, `outline: none` without replacement.
2. **Manual semantic review** — inspect heading hierarchy, ARIA landmarks, landmark nesting, focus management.
3. **Keyboard flow review** — verify focus indicators, skip links, mobile nav traps.
4. **Screen-reader sanity checks** — `aria-label`, `aria-labelledby`, `role`, live regions.

## Quick Fixes Applied

### 1. Heading hierarchy (`app/page.tsx`)
- Changed journey milestone cards from `<h4>` → `<h3>`
- Changed program showcase cards from `<h4>` → `<h3>`
- This preserves the semantic level under their parent `<h2>` sections.

### 2. Section ARIA labels (`app/page.tsx`)
Added `aria-label` to unnamed sections:
- Partner logos → `aria-label="Partner logos"`
- Partnerships → `aria-label="Partnerships"`
- Impact stats → `aria-label="Impact statistics"`
- Career journey → `aria-label="Career journey"`
- Programs → `aria-label="Available programs"`
- AI support → `aria-label="AI career support"`
- Final CTA → `aria-label="Get started"`

### 3. Dashboard landmarks (`app/(portal)/dashboard/page.tsx`)
Added `aria-label` to mobile sections:
- Dashboard hero, Next step, Counselor help, Progress overview, Certifications, Next actions, Priority action, Career path, Application journey, Points and rewards, Recommended programs / Next milestones, Quick actions, Career voice assistant

Fixed heading hierarchy:
- Recommended program cards: `<h4>` → `<h3>`

Wrapped career path in `role="region" aria-label="Career path"`.

### 4. Apply page landmarks (`app/apply/page.tsx`)
- Sidebar: `aria-label="Application steps"`
- Main form: `role="region" aria-label="Application form"`
- Supplemental cards: `role="region" aria-label="Program information"`

### 5. System page alt text
- `app/error.tsx`: logo `alt="WorkforceAP logo"`
- `app/not-found.tsx`: logo `alt="WorkforceAP logo"`

### 6. Signup form decorative elements
- Password strength bars: added `aria-hidden="true"`

## Larger Issues Needing Design Changes

| Issue | Effort | Why it needs design |
|-------|--------|---------------------|
| **Color contrast on funding chips** — the gold/yellow chip text (`#FFBB00` on light backgrounds) may fail WCAG AA for small text | 1–2 hrs | Need to darken text or add a darker background variant |
| **Mobile bottom nav icon-only labels** — while labels exist below icons, the tap target size and visual distinction for active state could be stronger | 2–3 hrs | Design review for touch targets ≥ 48×48dp and active-state indicators |
| **Dashboard desktop view lacks `<main>` wrapper** — the desktop view is inside a plain `<div>`; the root `<main>` wraps everything, but the desktop/mobile split means some assistive tech sees duplicate content | 3–4 hrs | Refactor to use a single `<main>` with conditional children instead of two parallel DOM trees |
| **Form error color alone** — `var(--color-accent)` (crimson) is used for errors; some color-blind users may not distinguish it from body text without additional icons or borders | 2–3 hrs | Add error icons + left-border pattern consistently across all forms |
| **Program card images** — `opacity: 0.7` on card images may reduce perceived contrast for text overlays; no text directly overlays, but decorative contrast is low | 1 hr | Review image treatment for visibility |

## Recommendations

1. **Install `@axe-core/react`** in dev mode to catch heading skips and missing labels during development.
2. **Run a screen-reader smoke test** (NVDA + Chrome, VoiceOver + Safari) on the apply flow after any future form changes.
3. **Add an a11y regression check** to CI: `axe-core` CLI against the built HTML for `/`, `/apply`, `/login`, `/dashboard`.
4. **Audit remaining portal pages** (`/dashboard/jobs`, `/dashboard/ai-tools/*`, `/admin/*`) with the same checklist.
5. **Document the `wa-sr-only` pattern** for new engineers — it works because Tailwind generates it, but it’s not visible in source CSS.
